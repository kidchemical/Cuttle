# Script distribution audit

Date: 2026-10-06. Scope: **77 tracked files**: every tracked file in `src/scripts/`, `.cuttle/scripts/`, `.cuttle_global/scripts/`, plus the three root launch/build scripts. This includes three support files (`README.md`, `.gitkeep`, scanner policy), not just executables. Recommendations only; no scripts were executed, changed, moved, or deleted by this audit. Findings describe the reviewed working-tree contents; commit-specific scanner exceptions retain their historical file paths.

Reviewed `AGENTS.md`, `docs/architecture/ARCHITECTURE_PRINCIPLES.md`, `docs/architecture/repository-map.md`, `docs/architecture/extension-boundaries.md`, and `docs/architecture/development-instance-safety.md`. Inventory came from `git ls-files`; source contents, Python structure/effects/path literals, imports, action recipes, documentation and test references were examined. “Caller” means a source-level invocation/import, not proof that a process is currently running. “None found” means no tracked caller found, not proof that an install-local launcher never uses it. No live databases, credential files or environment values were inspected; credential variable names below contain no secret values. This is a static suitability audit, not execution validation or a full-history secret scan.

## Recommended policy and main findings

- **GitHub should contain runtime code and useful contributor/release tooling.** An installed runtime can omit documentation capture, asset generation and shadow-test tools. A development script is not automatically an unwanted GitHub leftover.
- **Do not purge `src/scripts/utilities/`.** Most of it is imported production code for harness execution, resume, steering, usage and Git UI.
- **Exclude obsolete setup/example leftovers:** `example_project_setup.py`, `hello_world.py`, `update_project_paths.py`; the old drive updater has an executable `F:` → `E:` default and a broken database-root calculation.
- **Local model servers are user-owned (done):** the daemon and Flask no longer start, stop or kill llama.cpp (the `F:\llama.cpp\start-qwen-coder.ps1` fallback and the on-demand launch prompt are gone); Cuttle only connects to the configured endpoint.
- **Windows firewall helper repaired:** `enable_lan_firewall.ps1` now creates LocalSubnet + Private-profile rules only, replaces earlier open rules, and reads ports from `src/.env`. The phone isolation test now scopes and removes its temporary rule and URL reservation.
- **Mesh updates need an end-to-end repair before being advertised as preserving user work.** The safe standalone checkout helper is bypassed by the active executor's destructive update path; see below.
- **Optional README/promo tools are maintainer tooling, not Cuttle runtime.** Keep the reusable README capture chain on GitHub; the Blender sculpture and launch promo are optional media-production assets. The external Playwright MCP launcher and redundant Muse shim have no confirmed bundled caller.

Disposition legend: **Ship** = GitHub + applicable runtime/setup distribution; **Dev** = GitHub contributor tooling, omit from end-user runtime; **Optional** = explicit support/media tool, not default install; **Exclude** = recommend retiring from tracked distribution or retaining only as personal/history material. “Repair” is a prerequisite/recommendation for future work, not a change made here.

**Mesh preservation gap (confirmed source path):** `src/api/device_workers/executor.py` materializes updater bytes, calls `_git_stash_and_pull`, then launches PS with `-SkipPull` or Bash with `--skip-pull` (roughly lines 592–664). Despite its historical name, `_git_stash_and_pull` executes `git fetch --all --prune`, `git reset --hard <upstream>` and `git clean -fd`, returning `stashed=False` (lines 732–809). Thus the live job bypasses `client-update-checkout.py` entirely and can discard tracked modifications/local branch work and untracked nonignored files. The safe helper's tests do not establish that this executor path preserves work. Additionally, embedded scripts locate the checkout helper beside their own temporary path; a future change that drops skip-pull must also deliver/resolve the helper correctly. Repair belongs to the update owner, not deleting distribution scripts.

## Distribution follow-through (future work only)

1. Retain all harness/Git runtime utilities and action/deployment dependencies; folder names are not the distribution boundary. Keep project/global action ownership intact.
2. Repair daemon-local startup fallback, configured-port bridges, broad firewall/recovery/process matching and **executor-level update preservation** before documenting portable/safe setup guarantees.
3. Retire obsolete examples/drive updater; preserve intentional generic migration and shadow tooling on GitHub. If demo/media tooling remains, document opt-in effects/dependencies and remove obsolete Discord-surface claims.
4. For a lean installed package, omit contributor captures/build/version/chime generators, hook policy and shadow harness only where their workflows are intentionally unavailable. Preserve generated product assets, not generated fixture chats/media scratch/config/keys.
5. Before any later removal, update the concrete caller/action/doc/test references above. No removals, script edits, runtime changes, network actions or test executions were part of this audit.
