# Chat attachments (images / PDFs / voice clips)

- No CLI harness (Cursor, Codex, Muse, Hermes) accepts image input. `src/api/vision_prepass.py` turns uploads into a text digest: **Claude vision → OpenAI vision**, and reports the provider error inline rather than degrading into a silent "(no text found)" — otherwise the agent confidently says no image arrived.
- The pre-pass runs in `/api/chat` **above every slash-agent handler** (`_run_attachment_prepass`, just after the starred sticky prefix). It used to run at the bottom, so `/cursor`-badged turns reached the CLI with no description and persisted no attachment metadata.
- The digest is **appended**, never prefixed — each handler matches `^/cursor`/`^/muse`/… against `message_content` and slices the prompt off the front.
- History stores the short `[Attached: …]` note plus `metadata.attachments` (`filename`/`mime`/`url`), not the digest (`_attachment_history_text`). That metadata is what re-renders thumbnails after a refresh; without it the image disappears.
- Uploads land in `<home>/output/uploads/{session}/`, served via `/output/…`. `resolve_upload_refs` rejects any client path outside that root.
- **Voice clips** (composer mic button, flag `composer_voice_clip`, owner `src/web/js/chat/chat_voice_clip.js`) are ordinary attachments: `/api/upload` takes `vision_prepass.UPLOAD_EXTS` (images, PDF, audio). With live text on (default), `chat_voice_clip_text.js` types each phrase into the composer while recording, as one editable block per clip that leaves with its chip; such a clip is sent `transcribed: true` and the pre-pass skips it, because the message already carries its (possibly corrected) words. Otherwise the pre-pass transcribes the clip through `api.voice_stt` into the digest ("voice clip — transcript of what the user said"), reporting a failed transcription inline. History keeps the clip (an audio player in the bubble). Pressing Send while recording stops, attaches and sends the clip.
- **Speech to text is one setting** (`api.voice_stt.settings`, key `voice_stt`, Settings → Voice → Speech to text, `GET/POST /api/settings/voice-stt`): provider = any `api.model_providers` entry declaring `audio_transcription` (OpenAI, `local` = user-managed OpenAI-compatible server with its own address, ElevenLabs Scribe) or `browser` (Web Speech recognizer, client-only, never reaches the server); plus model, live text on/off and the longest clip (default 10 min). Voice mode's server transcription uses the same provider. A new provider only needs `audio_transcription` + a `transcription.default_model` in its manifest and `transcribe()` in its adapter.
